# Run autocode one ticket per session

The `autocode` workflow refreshes the direct Task and Bug children of its Azure delivery HU before every selection, pins the first unblocked ticket by creation time and ID, and runs that ticket in a clean OpenCode session. OpenCode advances only after an explicit `IMPLEMENTATION_READY` outcome and a validated manifest. The coordinator then creates or reuses the canonical HU-targeted PR, publishes evidence and cumulative effort, verifies every completion gate, moves the ticket to `Done`, and cleans the exact ticket branch. The marker is terminal for the OpenCode subprocess even when the provider leaves its streams open, and the provider session is deleted exactly once through `opencode session delete <sessionID>`; an explicitly absent session is idempotent, while another deletion failure stops with a sessionless checkpoint. Recovery resumes the persisted coordinator phase without invoking OpenCode to repair Azure metadata. Cleanup refuses a dirty worktree, and the queue refreshes only after checkpoint removal.
