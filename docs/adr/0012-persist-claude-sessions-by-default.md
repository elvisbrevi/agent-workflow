# Persist Claude sessions by default and fail closed toward a fresh worker

Claude fresh-worker launches persist the session transcript by omitting `--no-session-persistence`, mirroring the Claude CLI's own default. An operator who needs an ephemeral session can opt out by setting `disable_session_persistence = true` on the Claude profile; the runner translates that opt-out into `--no-session-persistence` and the checkpoint records its existing `session_id=unavailable` sentinel rather than an identifier that can never be honoured. When the captured session id cannot be confirmed in the runtime adapter's own store — because the session is missing, the transcript is unreadable, or the adapter cannot determine resumability — recovery fails closed toward a fresh worker constrained to the same issue rather than aborting or replaying an unsafe `--resume`.
