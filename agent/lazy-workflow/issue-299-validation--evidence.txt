Issue #299 -- Express the five authority profiles as Codex execpolicy rules
in a Codex authority home (ADR-0033, ADR-0021)

Five hand-written execpolicy rules files (agent/lazy-workflow/codex/*.rules)
carry the same prohibitions as opencode/authority.json and claudecode/*.json,
generated from neither: `prefix_rule(pattern=["git","push"],
decision="forbidden")` is the Codex analogue of OpenCode's `"git push*":
"deny"` and Claude Code's `Bash(git push:*)`. `lazy-review.rules` additionally
forbids `apply_patch` -- the shell-intercepted command Codex uses to edit
files -- matching Claude Code's Edit/Write/NotebookEdit denial and OpenCode's
`"edit": "deny"`. Committing stays unforbidden in the two `-code` profiles,
and no profile forbids `lazy-workflow` itself.

`assembleCodexAuthorityHome` (src/prompts/codex-authority-home.ts) builds a
Codex home for a fixed profile: writes only that profile's rules into
`rules/<profile>.rules`, symlinks `auth.json` and `skills/` from the operator
home, and never links `config.toml`. `utility/lazy-workflow/CODING-AGENTS.md`
now names all three authority formats and states none is generated from
another.

Out of scope for this issue (per its own text): wiring `codex` into the
AgentCli type / CLI dispatch (src/coding-agent/agent-cli.ts,
create-coding-agent.ts). Not touched.

A code-review pass (Standards + Spec axes, run in parallel) found no findings
on either axis; a self-review during validation found one strict-mode
TypeScript issue in the new test (RegExpMatchArray indexing under
noUncheckedIndexedAccess), fixed by defaulting the capture groups.
